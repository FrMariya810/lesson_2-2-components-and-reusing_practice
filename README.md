# Практика 2/2. Одна карточка, два списка

Соберите `booking-card` и замените им обычные карточки заявок. Данные принадлежат приложению; компонент показывает одну заявку и сообщает о нажатии. Задания выполняются по порядку. Первые шаги дают образец, последние связывают несколько частей приложения.

## Старт

Откройте эту папку в редакторе: рядом должны лежать `package.json`, `README.md` и `src`. Нужны Node.js 22.12+ и npm 10+. В терминале этой папки:

```bash
npm ci
npm run dev
```

Откройте адрес из терминала, оставьте сервер работающим. Команды проверки запускайте во втором терминале в той же папке. После изменений компонента обновляйте страницу целиком: регистрация тега действует до перезагрузки. Если npm не найден, проверьте `node -v` и обратитесь к преподавателю с текстом ошибки.

Уже работают форма, обычные карточки, подтверждение и счётчик. Компонент намеренно не зарегистрирован, его методы отмечены `П2`–`П10`. До задания 9 списки внизу используют прежние карточки. Верхняя лаборатория проверяет компонент отдельно и не меняет заявки в списках. Перезагрузка сбрасывает оба опыта; данные нигде не сохраняются.

| Файл | Назначение |
| --- | --- |
| `src/components/booking-card.ts` | Основная работа: структура, данные, событие, lifecycle |
| `src/main.ts` | Подключение компонента к двум спискам |
| `src/models/booking.ts` | Типы и исходные заявки |
| `src/style.css` | Стили страницы для опыта с изоляцией |
| `src/lab.ts`, `src/legacy-card.ts` | Готовый стенд и обычная карточка; менять не нужно |

## 1. Запустите основу и измените данные

На странице должны быть Анна и Иван в «Все заявки», только Анна в «Подтверждённые», участников **2**. В `src/models/booking.ts`, метка `П1`, измените у Ивана `seats: 1` на `seats: 2`. Сохраните и обновите страницу.

**Проверка:** у Ивана 2 участника, общая сумма **3**. Верните `seats: 1`, обновите страницу: снова **2**. Выполните `npm run typecheck`: ошибок быть не должно. Дальше исходные данные не меняйте.

## 2. Зарегистрируйте свой элемент

В конце `src/components/booking-card.ts`, **после закрывающей скобки класса**, вместо комментария `П2` добавьте:

```ts
customElements.define('booking-card', BookingCard)
```

В `src/main.ts` у метки `П2` добавьте импорт, который выполняет модуль:

```ts
import './components/booking-card'
```

Обновите страницу, в лаборатории нажмите «Создать образец». **Ожидание:** строка «Создан один экземпляр», «Подключён: да». Сама карточка пока пустая, это нормально. В DevTools → Elements внутри `#sample` есть `<booking-card>`. Если регистрации нет, проверьте обычный импорт: `import type` его не заменяет.

## 3. Создайте внутреннее дерево

В конструкторе `BookingCard` уже подготовлены `style`, `article` и узлы карточки. Вставьте у `П3`, после `article.append(...)`:

```ts
const root = this.attachShadow({ mode: 'open' })
root.append(style, article)
this.render()
```

Обновите страницу и снова нажмите «Создать образец». **Ожидание:** «Ожидаю данные», кнопка «Подтвердить» недоступна. В Elements раскройте карточку: внутри `#shadow-root (open)` находятся стиль и `article`. `attachShadow` остаётся только в конструкторе, не переносите его в `render`.

## 4. Передайте объект через свойство

В `booking-card.ts` замените **тело** setter `set booking`, включая `void value`, на:

```ts
this.current = value
this.render()
```

В `render`, после готовой проверки `if (!booking)`, у `П4` добавьте:

```ts
this.nameText.textContent = booking.name
this.seatsText.textContent = `Участников: ${booking.seats}`
```

Обновите страницу: «Создать образец» → «Данные Ивана» → «Группа из 3». **Ожидание:** имя Иван, число меняется с 1 на 3; в диагностике «Дерево: то же», «Кнопка: та же». Кнопка пока выключена. Общая сумма в нижних списках остаётся **2**, это отдельные данные.

## 5. Отобразите состояние заявки

В том же `render`, у `П5`, добавьте три обновления. Используйте условие `booking.status === 'confirmed'` и тернарный оператор, как в обычной карточке `src/legacy-card.ts`:

| Узел / свойство | Для `new` | Для `confirmed` |
| --- | --- | --- |
| `this.statusText.textContent` | `Новая заявка` | `Подтверждена` |
| `this.button.textContent` | `Подтвердить` | `Подтверждено` |
| `this.button.disabled` | `false` | `true` |

После обновления страницы создайте образец. Нажмите «Данные Ивана» → «Подтверждённые данные» → «Данные Ивана». **Ожидание:** текст и доступность меняются в обе стороны; кнопка остаётся той же. Нажатие внутренней кнопки ещё ничего не делает. Пройдите `npm run typecheck`. Это точка проверки перед событиями: если результат не совпал, покажите преподавателю setter и `render`; образцы для восстановления находятся в заданиях 3–5.

## 6. Настройте цвет через границу Shadow DOM

1. В конец `src/style.css` временно добавьте `button { background: #c45a16; }`. После перезагрузки создайте образец и передайте Ивана. Внешние кнопки станут оранжевыми, внутренняя останется синей. Нажмите «Проверить поиск»: обычный поиск даёт `null`, через `shadowRoot` кнопка находится.
2. Удалите временное правило. Внутри строки `style.textContent` компонента, метка `П6`, замените только `background: #355bd4` на `background: var(--booking-accent, #355bd4)`.
3. В конец `src/style.css` добавьте `#sample { --booking-accent: #087f72; }`. Перезагрузите, создайте образец, передайте Ивана: его кнопка зелёная, внешние кнопки обычного цвета. Переменную оставьте.

Меняется внутреннее правило компонента, использующее наследуемую переменную. Обычный внешний селектор внутрь не проник. В этом опыте нужна **новая** заявка: для подтверждённой действует отдельное оформление выключенной кнопки.

## 7. Отправьте событие наружу

В `booking-card.ts` поле `onConfirm` уже содержит проверку наличия новой заявки. После неё, у `П7`, добавьте:

```ts
this.dispatchEvent(new CustomEvent('booking-confirm', {
  detail: { id: this.current.id },
  bubbles: true,
}))
```

В тело `connectedCallback` добавьте:

```ts
this.button.addEventListener('click', this.onConfirm)
```

Перезагрузите, создайте образец и передайте Ивана. Нажмите **внутреннюю** «Подтвердить» дважды. **Ожидание:** счётчик лаборатории 1, затем 2; статус остаётся новым. Лаборатория только считает сообщения. Ничего не меняйте в `current.status` и не импортируйте массив заявок в компонент.

Отправитель здесь `this`, то есть host. Для будущего слушателя на контейнере включено `bubbles`; событие не отправляется из внутренней кнопки, поэтому `composed` для этого пути не требуется.

## 8. Снимите обработчик при отключении

В `disconnectedCallback`, метка `П8`, вызовите `removeEventListener` для той же кнопки, события `click` и **той же функции `this.onConfirm`**. Ориентир синтаксиса: строка подключения в задании 7. Новую стрелочную функцию не создавайте.

После перезагрузки: «Создать образец» → «Данные Ивана» → один внутренний клик. Событий **1**. Далее:

1. «Отключить» → «Клик по отключённой»: карточки нет, событий по-прежнему **1**.
2. «Вернуть» → один внутренний клик: событий **2**, дерево и кнопка прежние.
3. Повторите отключение, проверочный клик и возврат ещё дважды. После каждого возврата сделайте один внутренний клик: итог **4**.

Клик вне документа проверяет именно снятие слушателя. Одного отсутствия дублей после возврата для этой проверки недостаточно.

## 9. Подключите компонент к двум спискам

Теперь работайте в `src/main.ts`. Владелец массива, синхронизация и операция `confirmBooking(id)` уже готовы.

1. У `П9` вверху добавьте `import type { BookingCard } from './components/booking-card'`. Обычный импорт из задания 2 оставьте.
2. Замените тело `makeCard` следующим образцом:

```ts
const card = document.createElement('booking-card') as BookingCard
card.booking = booking
return card
```

3. Замените тело `updateCard` присваиванием `(card as BookingCard).booking = booking`. Это повторная передача данных существующему экземпляру. Приведение допустимо здесь, потому что `makeCard` теперь создаёт зарегистрированный элемент этого типа.
4. В обработчике `booking-confirm`, у последней метки `П9`, вызовите `confirmBooking(id)`. Удалите ставший ненужным импорт `legacyCard, updateLegacy`. Сам файл старой карточки можно оставить.

Перезагрузите. В Elements в обоих списках теперь `<booking-card>`. У Анны две отдельные карточки. Подтвердите Ивана **в левом списке**: он появляется справа, обе его кнопки выключены, участников **2**, получено событий **1**. Приложение не ищет кнопку через `shadowRoot`: оно получает id из события и заново передаёт данные карточкам.

## 10. Расширьте общий компонент и проверьте сборку

В `booking-card.ts`, `render`, у `П10` заполните готовый `this.groupText`: при `booking.seats === 1` текст `Индивидуально`, иначе `Группа`. Другие файлы ради этой подписи не меняйте. Узел уже создан и добавлен в конструкторе.

Выполните `npm run build`, затем `npm run preview`. Откройте **адрес preview** из терминала. Начните с перезагрузки и пройдите сценарий:

| Действие | Результат |
| --- | --- |
| Исходное состояние | Анна и Иван слева, только Анна справа; участников 2; подпись «Индивидуально» |
| Подтвердить Ивана слева | По две карточки в списках; участников 2; событий 1 |
| В форме ввести имя Мария, участников 3, нажать «Добавить заявку» | Слева 3 карточки, справа 2; участников 5; у Марии «Группа» |
| Подтвердить Марию слева | По 3 карточки; участников 5; событий 2; у обеих карточек Марии «Группа» |
| Ввести имя Тест и участников 6, отправить | Сообщение о числе от 1 до 5; новой карточки нет; участников 5 |
| Перезагрузить страницу | Исходные 2 участника и 0 событий |

Одно подтверждение выполните клавиатурой: Tab до нужной кнопки, затем Enter. Если исправляете код после сборки, повторяйте `build` и обновляйте preview.

## Что показать

Преподаватель может попросить изменить знакомую подпись или число участников и проверить результат без ИИ. При затруднении разберите его с преподавателем; отдельный отчёт и PR для практики не нужны.

**Помощь ИИ:** можно уточнять понятия, разбирать свой код и получать локальную подсказку. Пункты выполняйте сами, без генерации готовых правок и генеративного автодополнения. Образцы этой практики и лекции разрешены. Если использовали помощника, при показе кратко назовите инструмент, вопрос и выполненную самостоятельно проверку. [Правила помощникам](AGENTS.md).
